# Phase 4 release blockers and completion report

**Production readiness: NOT READY. Staging: prepared, deployment verification blocked.**

This report supersedes the Phase 3 dispositions where explicitly stated below. Phase 3 evidence remains historical evidence. No production resources were changed and no real credentials were rotated. The workspace's Git `origin` was changed to the user-requested GitHub repository; no push was performed.

## Approved product decisions

- Free **3**, Pro **10**, Max **25** metered units, shared across all document types in one account.
- One unit means **each outbound AI provider request, including fallback/retry attempts, plus each server PDF generation**. Local browser exports remain **unmetered** and do not create server artifact history. There is no billing change for browser exports.
- All plans use **20 hours from the first accepted metered request**. Quota denial and status inspection do not start a window. Admins can configure limits and window length. `monthly_quota`, `daily_quota` and `documentsPerDay` remain legacy wire/database names; they no longer imply a calendar reset.
- Restricted HTML, scalar field placeholders and embedded PNG/JPEG assets are supported for uploaded templates. Publication requires administrator review. Administrators choose owner-only or public availability through a reviewed version.
- Groq and Resend are the initial provider integrations. Admins can select Groq/Claude, enable/disable Paddle/PayHere and Firebase, select local/Supabase storage, and select Resend/disabled email delivery. Secrets remain operator-injected service configuration.

**Still requiring owner decisions:** Free/Pro/Max retention defaults, retroactive retention changes and legacy quota cutover. Explicit retention settings are enforced for new server artifacts; unset retention preserves existing behavior. Owner-only means one account: organization-wide/company membership and sharing are not defined by the current data model. An API request that dies after its quota reservation but before the external provider receives the request cannot be proved sent without provider-side receipts; there is no claim of exactly-once external charging.

## Remaining deployment prerequisites

1. A Docker daemon and a host that supports sandboxed Chromium user namespaces or an approved sandbox implementation. The sandbox was not disabled to obtain a passing test.
2. A sanctioned sanitized legacy PostgreSQL copy plus frozen Redis counters/receipts and backup restore evidence. Fresh fixture migrations do not substitute for these.
3. Owner-approved TOTP encryption/key rotation and revocation of exposed/old credentials; no automatic production rotation occurred.
4. Identified staging Groq project; a valid Resend staging key, verified sender/domain and designated test recipient. Read-only Groq authentication passed; Resend authentication returned 401. Neither result establishes a complete staged workflow.
5. Later-phase Paddle sandbox API/webhook secrets and matching USD prices; PayHere sandbox merchant and OAuth App ID/Secret, verified timestamp offset, registered callback and merchant permissions; Firebase staging project/web app configuration; Claude staging key; Supabase staging project/private `documents` bucket/service-role key.
6. Owner retention, legacy quota cutover and company sharing decisions; approved automation webhook destinations/receiver idempotency and manual review; image digest/SBOM scans, the unresolved build advisory decision, and actual load/accessibility/responsive/DR sign-off.
