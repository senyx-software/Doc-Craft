Configurable inference endpoints retain HTTPS/DNS/IP/allowlist SSRF restrictions; secrets stay server-side. Model/provider details remain absent from regular-user responses.

Production adds private networks, TLS, non-root application runtimes, selected read-only secret mounts, forced-command deployment SSH, cleared controller environment, exact registry/digest allowlists, immutable config versions, admin edge source-CIDR restrictions, local and GitHub deployment enable gates, minimal Actions permissions and a separate infrastructure approval boundary. Residual exposure: existing env-only loaders expose scoped secrets to the owning process/Docker administrators. Compose file secrets are not a managed secrets vault. ACME/private CA/service-certificate renewal and encrypted off-host backups are operator responsibilities. Broad Docker/root permissions remain privileged. The deployment identity must not join Docker or receive an unrestricted sudo rule. Avoid putting a runner handling untrusted PR code on the production VPS.

No committed backend provider secret was confirmed after classifying historical hash/prose/synthetic/public-client matches. Private ignored provider credentials were not tested against external services or rotated; see redacted findings. No production account, registry or SSH server was accessed.

Native PDF sandbox readiness fails in this environment. The 1.7B real-model tool accuracy is insufficient. These blocks require NO-GO for production activation, not a claim that static policies alone prove deployment security.
