# GitHub Actions CI/CD

`ci.yml` validates PRs targeting master, master pushes, v* tag pushes and manual dispatch. PR/manual runs never deploy. Validation installs locked Node/Python dependencies, generates Prisma clients, lints/builds both frontends/all backends, runs shared/chat/admin/quota/document and browser-fixture tests, runs real disposable PostgreSQL migration/grant tests, checks immutable/destructive SQL policy, scans dependencies/secrets/assets, validates Actions/Compose/Terraform, and builds/scans all distinct production Docker targets. A separate blocking job scans every pinned infrastructure/build-base image.

After successful master/release-push validation, the reusable `build-and-push.yml` publishes gateway/auth/notification/payment/quota/chat/pdf/document/analytics/admin-api/admin-ui/user-ui/migration images to GHCR. Tags include sha-<commit> and an approved vX.Y.Z tag where applicable. No latest tag is relied upon. BuildKit publishing reuses already-validated CI target caches plus service caches, provenance/SBOM attestations are enabled, images are vulnerability-scanned by exact digest and publication is checked. Per-image digest artifacts are assembled into a complete validated release.json manifest. No production secrets enter builds.

Release tags must match v<number>.<number>.<number> and their commit must be reachable from origin/master. Both CI and publishing check ancestry. Configure tag rules so only authorized maintainers can create/update release tags; do not rely on a check inside an attacker-modified workflow as the sole protection.

`deploy-production.yml` receives only the current run's manifest, waits for the protected production environment, verifies SSH host keys, and sends JSON to the forced controller command. It runs only when repository variable PRODUCTION_DEPLOY_ENABLED=true. The VPS independently requires /etc/doccraft/production-enabled. Production concurrency has cancel-in-progress=false; remote flock and disconnect-resistant critical migration execution prevent competing deployments. Routine application deployments do not run Terraform.

Third-party Actions use API-verified full immutable commit SHAs. permissions default to contents:read; package write exists only for publishing. PR jobs have no production environment, deployment SSH key, cloud credential or registry write permission. No pull_request_target or privileged workflow_run checkout is used. CI tool binaries have committed checksums in ci-tools.json. GITHUB_TOKEN is short-lived for GHCR publishing; the VPS needs a separate read-only registry identity.

Local actionlint validation passed. Actual hosted workflow execution, GHCR push/pull authentication, attestations and SSH delivery remain unverified until operator repository/VPS setup. Required branch/environment/tag settings are in report 10. [GitHub secure use](https://docs.github.com/en/actions/reference/security/secure-use) supports immutable action pins, minimal permissions and environment review boundaries.

Live dependency audit found nine advisories in certifi/Pillow; pins were updated to certifi2026.10.19/Pillow13.0.0, strict pip-audit is clean, and195 admin/73 document regressions pass. Remote registry Trivy scans report blocking vulnerabilities in pinned upstream images; CI intentionally refuses publication until findings are resolved. See evidence/dependency-security.json and base-image-scans.json. Scans require network access and may fail closed on database/registry outages.

Enable GitHub Actions workflow-failure notifications for the operator group. A failed readiness gate exits nonzero and produces a failed production job with a bounded status summary; GitHub delivery depends on operator notification settings. No unconfigured external email/Slack webhook is invoked.
