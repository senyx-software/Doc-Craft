# Staging vulnerability review — 2026-10-25

Deployment remains blocked. The blanket unfixed-OS option was rejected and removed. Every HIGH/CRITICAL image vulnerability and secret continues to block; production retains its existing scan command. No exception is approved or active.

## Evidence and scope

The [CI run at commit d483327](https://github.com/senyx-software/Doc-Craft/actions/runs/40191057760) produced eight image reports: five blocked images contain 357 package/CVE rows representing **43 distinct CVEs: 39 HIGH and four CRITICAL**. Node runtime and Python each represent multiple app services; these are representative build targets, not 15 independently published registry manifests. No app release has been deployed.

The earlier policy document listed totals and three examples, but omitted the full CVE inventory and overlooked fixes available in newer Debian releases. This report replaces that proposal.

## Exploitation evidence and uncertainty

The official [CISA KEV feed](https://www.cisa.gov/sites/default/files/feeds/known_exploited_vulnerabilities.json) was fetched on 2026-10-25; its catalog release is `2026-10-23T19:30:18.9209Z`. None of these 43 OS CVEs or seven additional application CVEs is listed. KEV absence does not establish that a CVE is unexploited. Public proof-of-concept and in-the-wild status are not exhaustively established, so no finding is granted an exception on this evidence.

[FIRST EPSS](https://www.first.org/epss/) data dated 2026-10-24 covers 42 of the 43 image CVEs. It is a forecast, not an exploitation verdict or an approval criterion. Individual scores and CVSS vectors are retained in findings.json. A missing score remains unknown. Scanner severity is preserved even where vendor CVSS assessments differ.

The exposure assessments below are static inferences from the committed app, Compose configuration and scanned package inventories. They are not live EC2 attestations. The PDF renderer runs headless with JavaScript disabled and request interception, but still parses user-derived text, HTML and embedded assets. Its production sandbox/capability behavior has not been verified on EC2. PostgreSQL is not published as a host port and uses scoped roles/TLS in configuration; XML and other compiled-in features still need a call-path review.

The inventories show no cupsd, systemd-homed, Thunderbird, Python libxml2 binding or X-server package/binary in the affected reviewed images. These are applicability leads requiring evidence tied to the exact image/profile, not automatic suppressions. Browser request interception does not prove that every native parser/resource loader has equivalent restrictions.

## Remediation before exception review

**Nineteen of the 43 CVEs have a vendor fix recorded in Trixie.** Bookworm has no fixed version for the scanned rows, but that is insufficient justification for an exception. Prefer rebuilding on a supported newer or smaller base, applying its security updates, then rescanning the actual runtime. Do not mix unstable packages into Bookworm to satisfy a scan.

Node/Python Trixie bases remove the reported zlib, SQLite, OpenSSL, gzip and some util-linux findings and leave eight distinct local/privileged-helper CVEs. These are raw base scans; complete rebuilt service images still require scans, compatibility tests, migrations and sandbox/PDF checks. No production Dockerfile/base was changed for this comparison.

PostgreSQL Trixie still reports CRITICAL CVE-2026-6653, and introduces HIGH CVE-2026-24882 (GnuPG/tpm2daemon) and CVE-2026-86139 (libxml2 URI escaping) compared with the current image. It is not a clean replacement. Evaluate a smaller supported PostgreSQL 17 image or a patched libxml2 build, including locale, extension, TLS, backup and initialization compatibility. Do not approve a simple tag change on the basis of lower totals. Exact pins and compressed candidate reports are in [candidate-scans/](candidate-scans/) and findings.json.
